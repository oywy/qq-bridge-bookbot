# 书单图片与 QQ 语音记录设计

用户选择「先用 QQ 自带转写，失败保留待处理」，沿用前一轮提出的图片识别 → 书单抽取方案。扩展已完成的本地 `codex/bookbot-mvp`，基础提交 `feb9c1e`；不修改 ASR 项目、不配置账号、不连接实际服务。

## 行为

- 对已授权书单群的消息，持久记录文字附言、图片定位信息或语音消息类型；纯图片和纯语音也入队。原有去重、真实发送者、消息 ID、引用、时间和撤销权限继续生效。
- 后台处理媒体：图片沿用桥接现有的安全获取、5 张/4 MiB/64 百万像素限制，以专用无工具 DSH 会话识别可见文字；语音只按原消息 ID 调用 SnowLuma 的 `fetch_ptt_text`，不下载音频、不增加 ASR 服务。
- 保存识别文本和识别来源，原始文字附言不覆盖。识别结果有严格形状和长度限制。空白语音转写、超时、缺失图片或不合法模型输出都保留待处理，按既有重试间隔再试；失败消息不阻塞同群后续文字。
- 成功识别缓存入库，失败重试和重启不必重新识别已有结果；处理中撤销优先，不能重新写入识别文本或讨论条目。
- 识别内容进入原来的书单抽取，命令只从真实文字解析，图片/语音识别文本不能触发书单命令或其他工具。
- 截图/封面单独只能作为提及和截图内容来源；图片中的第三方推荐或评价不能算上传者本人的推荐、评价。明确文字附言或语音发言才能记为该人的推荐/评价。当前来源提供图片 OCR 时，非空个人观点必须逐字来自原始配文或 QQ 转写，避免配文证据夹带截图观点；关闭图片渠道后按原文字/语音行为处理，不向模型提供当前图片 OCR。提取证据必须属于对应消息的原文或保存的识别文本，不能伪造来源。
- 查询给图片条目标明「图片识别／分享者」，语音条目标明「QQ 语音转写」；字数、状态各自标记真实来源类型和时间，图片识别的字数不冒充群友亲口报告。
- 既有库幂等迁移，文字历史行为和统计不变。撤销及普通聊天到期清理同时清除媒体定位和识别文本，取消去重标记继续保留。
- 配置在 `bookbot.media` 中控制 `images: true`、`voice: "qq"`；总功能仍默认禁用、群白名单仍显式授权。关闭媒体渠道后，文字附言照常处理；当前待处理消息不分析已关闭渠道的识别缓存，既有历史条目仍可查询。图片需要当前配置模型支持图片输入。

## 边界与验收

不分析视频、合并转发或语音里的多说话人；不联网核实书籍，不新增定时推送。QQ 转写可能长期拿不到结果，记录仍保留等待重试或引用撤销；识别结果不能保证语义正确。

离线测试覆盖纯媒体采集、旧库迁移、同群上下文、缓存重启、逐消息重试、截图归属、语音身份、出处标注、来源校验、撤销竞态、识别命令不执行，以及真实桥接使用的图片获取/转写接口和 DSH 会话清理。继续运行原有 24 项行为测试、预设契约和完整离线回归，报告已知基线失败。真实 QQ 转写及模型图片识别能力需用户配置后联调，不能宣称已经实测。
