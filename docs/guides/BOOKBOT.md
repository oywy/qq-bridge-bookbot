# 群聊书单机器人 MVP

机器人安静记录已授权群里的在线小说讨论，按消息来源区分“提及、推荐、评价”，保存每个人自己的观点、风格标签以及群友报告的字数和连载状态。它不联网查书，不更新网站元数据，不定时主动发书单。

## 启用

使用支持 `node:sqlite` 的 Node.js（项目最低 22.13，离线测试使用 24.4.1；这些版本会显示 SQLite experimental warning）。先按项目 README 安装依赖和自行配置 SnowLuma、DSH。本功能不安装或启动 SnowLuma。

在 `config.json` 中增加以下配置，替换群号和管理员 QQ：

```json
{
  "ownerQQ": "123456",
  "allow": { "groups": ["654321"], "private": ["123456"] },
  "bookbot": {
    "enabled": true,
    "groups": ["654321"],
    "onlyBooks": true,
    "naturalLanguage": true,
    "batchMs": 15000,
    "maxBatch": 30,
    "contextMessages": 30,
    "contextChars": 12000,
    "retryMs": 60000,
    "timeoutMs": 120000,
    "voiceTimeoutMs": 30000,
    "media": { "images": true, "voice": "qq" },
    "rawRetentionDays": 7,
    "maxReplyChars": 3500
  }
}
```

`config.example.json` 默认 `enabled: false`、`groups: []`。书单内部的 `naturalLanguage` 默认启用，设为 `false` 可关闭自然语言回复，同时保留固定命令和安静记录。群号必须同时出现在 `bookbot.groups` 与既有 `allow.groups` 中；`deny.groups` 优先，任意一份白名单为空都不采集。`allowAllWhenEmpty` 不会扩大书单权限。更改这些配置后重启桥接。

安装/更新 DSH 预设（执行前应已按 README 准备自己的 DSH 环境）：

```bash
npm install
node scripts/setup-dsh.mjs
# 然后自行重启 DSH，使 book-extractor 预设生效
npm start
```

`setup-dsh.mjs` 的既有 bundle 安装现在包含 `book-extractor`。缺少这个专用预设时提取失败并保留重试，绝不使用默认或聊天预设。桥接控制台选择 `chat` 或 `reserved2` 才能收到群书单回复；`closed-agent` 仍只允许管理员私聊出站。已授权群的采集不依赖 DSH 聊天唤醒、潜水或当前模式。

`onlyBooks: true` 会关闭这些群的通用聊天提示、自动回复、唤醒及既有聊天会话的发送，并拒绝旧通用会话令牌的 MCP 读取和修改调用；书单命令仍可回复。设为 `false` 可以同时使用原有聊天模式与书单采集。书单命令回复继续经过原有敏感文本审计、CQ 转义与临发送权限复核。既有角色静默设置（`state/current-role.json` 的 `mode: "silent"`）仍会阻止群书单回复，包括排队期间切换为静默的回复；已授权消息采集继续进行。

## 群内使用

| 命令 | 行为 |
| --- | --- |
| `/书单 今天` | 上海时区今天零点以来的推荐 |
| `/书单 本周` | 上海时区本周一零点以来的推荐 |
| `/书单 近七天` | 含今天的七个上海自然日 |
| `/书单 查 书名` | 本群书名包含匹配，显示推荐和评价 |
| `/书单 推荐人 QQ号` | 此人在本群推荐过的书 |
| `/书单 找 科幻 慢热` | 匹配同时具有这些标签的提取记录 |
| `/书单 帮助` 或 `/书单` | 简短说明 |
| 引用原消息 + `/书单 撤销` | 删除那条原消息产生的全部条目 |

也支持 `@机器人 今天推书`、`@机器人 本周推书`、`@机器人 近七天推书`、`@机器人 查书 书名`。

自然语言不要求固定句式，例如 `@机器人 帮我找找我本周推过的科幻慢热小说吧`、`@机器人 昨天小甲推荐了哪些书`、`@机器人 星海拾光有哪些评价`、`@机器人 上周有哪些推书`。只有原 QQ 事件 @ 当前账号，或网关确认引用的是当前机器人在本群的消息，才申请自然回复。引用段自己声称的发送者不能触发；普通群聊仍安静记录。引用机器人明确列出的一本书后，可以说“这本有什么评价”，或分享自己的明确评价；机器人引用只帮助确定书名／作者，不能确定人员／昵称／标签映射、字数／状态或查询指令。本人观点必须来自本人的原始文字或 QQ 转写；当前来源或可用上下文中存在机器人引用时，观点要求逐字出现，不能经由上一条人类消息复制机器人评价。引用多个书名而指代不清时需补充书名。

提示限定书籍、小说、本群书籍记录、推荐和评价、作者和风格、群友报告的字数／状态及推书统计。天气、编程、闲聊、绕过规则及混有无关任务的请求固定回复 `这是不相关内容`。本群没有相关记录会说明暂无记录；指代不清、不能准确表达的条件、库外事实或自然语言撤销会提示补充条件。重名昵称会提示补充 QQ 号，“我”绑定真实请求者。按作者筛选、网上实时状态、排名等未支持条件需进一步说明，不能偷偷丢掉条件。模型只输出受限查询计划，本地 SQLite 同时应用时间、书名、人员、标签和提及／推荐／评价类型，模型不直接回答、不生成 SQL、不写数据库。

自然语言支持原始文字及启用的 QQ 语音。@机器人发语音可提问；@文字配图片时，OCR 可帮助确定书名。纯图片 OCR 不能执行查询或撤销，会提示补充自己的文字／语音问题。分享书籍的自然发言仍经过原有提取，只有实际保存了条目才回复“已记录”；未识别到条目会明确说明。查询与自己的推荐／评价混在一句话中时，提取仍保留明确的本人观点。昨天和上周使用上海自然日／周一至周一的范围。

只有原消息发送者或 `ownerQQ` 可以撤销。撤销产生持久取消标记，重复事件或正在进行的提取不会把条目恢复。引用应指向机器人上线后实际采集的本群原消息；其他群或其他账号的记录不可操作。

统计由 SQLite 对全部匹配记录计算，书数与推荐人数去重；单纯提及或评价不计为推荐。回复最多选择 8 本，每本列出本次查询匹配的最多 6 位推荐人、全历史“本群首次记录”和最多最近 4 条记录，总字符默认不超过 3500。空间不足时仍显示首本书名，优先显示匹配推荐人和带来源、时间的字数／状态报告，省略放不下的完整记录并注明；不会截短报告内容冒充完整事实。人数统计可以大于展示的人名数量；信息较多时用书名、推荐人或标签缩小范围。“本群首次记录”只指本库里的首次推荐，不代表现实里的最早推荐。

每本书的最近一次有效字数报告和最近一次有效状态报告单独显示，分别标明报告人、原消息和时间；两项可以来自不同消息，也可以早于当前查询时间范围。较新的普通评价不会遮掉报告。撤销报告消息会分别回退到更早的有效报告；没有剩余报告时不再显示该项。文字报告标为“群友报告”，语音标为“QQ语音转写报告”，图片中的数值标为“图片识别字数／状态”和实际分享者。两项可以来自同一消息的不同渠道；它们都不代表当前网站真实值。

## 图片与 QQ 语音

自然查询的最近 4 条记录遵守本次全部筛选条件，并标为“本次查询匹配记录”。首次推荐及最新字数／状态单独列出仍有效的历史来源；固定命令保持原有历史记录展示方式。

书单启用后默认 `media.images: true`、`media.voice: "qq"`。授权群的纯图片、纯语音以及带文字／Markdown 配文的消息都可入队，接收时只保存来源和必要媒体引用，后台再识别。关闭某个渠道（`images: false` 或 `voice: false`）仍会处理普通配文，也不会等待被关闭的媒体；当前来源与待处理／处理中上下文都排除已关闭渠道的缓存，已完成历史仍可查询和引用。

图片复用桥接既有安全获取路径：安全网关缓存文件名、网关 home 内经 realpath 验证的文件或通过 SSRF 保护的公网 URL。单条最多 5 张、总计 4 MiB、每张最多 6400 万像素，仅 PNG/JPEG/GIF/WebP；无法解析尺寸、部分图片无法获取或超限时，该原消息保留重试，不以占位文字冒充成功。OCR 只转写可见文字，没有可见文字可返回空文本，不猜书名、作者或观点。`cfg.dsh.model` 必须是既有 DSH 中实际支持图片输入的模型；本功能不新增模型目录或自动更换模型。只支持文字的模型可能拒绝图片输入，此时原消息留在待处理队列。真实模型支持情况需自行验证。

截图里的推荐或书评属于引用内容。纯 OCR 证据只能形成“提及”，`opinion` 为空；查询显示“图片识别 / 分享者”，不会把截图作者的推荐人数归给上传者。原始配文明确说“推荐这本”，且图片可证明书名时，可以记录分享者自己的推荐。图片里的字数、状态单独标注来源。当前来源向抽取提供图片 OCR 时，本人观点必须逐字出现在原始配文或 QQ 转写中；仅在截图出现的观点会拒绝，改写式观点也可能保守地留待重试。关闭图片渠道后，配文和语音沿用原有行为。

语音只调用当前 SnowLuma `httpUrl` / `accessToken` 的 `fetch_ptt_text`，参数是原 QQ 消息 ID。没有下载 `record` 的 URL／文件，也不需要额外 ASR、云服务或新的工具权限。QQ 平台转写不一定可用，也可能把书名同音字写错；空白、畸形、错误或超时响应都让该原消息保持待处理，默认 60 秒后重试。转写视为原发送者的话，可记正常推荐／评价，查询标为“QQ语音转写”。OCR 和语音各最多 12000 字；同一消息的图片 OCR 合计最多 12000 字。

同一消息含多个启用渠道时，全部准备成功后才提取该来源。成功识别分别持久缓存，提取失败或重启后复用；一条识别失败不会阻止同群后续普通文字。固定命令只从原始文字解析，截图和语音里的 `/书单` 不会执行；语音可以作为自然查询发言，但不能触发撤销。引用原消息后撤销会清除本地原文、媒体引用、识别文本、核实的机器人引用上下文和条目，持久取消标记阻止在途识别、提取或重复事件恢复它。

## 持久化、上下文与限制

- 数据保存在受既有 `state/` 权限保护的 `state/bookbot.sqlite`（以及 SQLite 的 WAL/SHM 文件）。机器人账号、群、消息 ID 共同去重；群之间没有共享书库。复制备份应在桥接停止后进行，或连同 WAL 一起保留。
- 所有已授权文本及启用的图片／语音消息都进入队列，没有关键词预筛选；包括 `text` 和 `markdown` 段的正文（兼容 Markdown 的 `data.text` / `data.content`）。命令消息由确定性的命令处理器消费，机器人自己的消息忽略。默认约 15 秒批处理，达到 30 条可提前处理。媒体错误仅保留该原消息；书籍提取错误或非法 JSON 保留准备完成的批次，默认 60 秒后重试；重启恢复未完成任务。
- 每批使用新的 DSH 会话，用后取消事件订阅并归档、释放模型缓存；没有可执行工具，也不向 QQ 发送模型文本。上下文只来自同一账号同一群：默认最近 30 条、最多 12000 字，优先加入引用消息。当前待处理原文不截断。无法明确确认“这本”指什么时应跳过。
- 回复申请及核实的机器人引用文字（最多 200 字）随消息持久化，升级旧数据库时旧消息默认不申请回复。自然规划同样使用新的无工具 DSH 会话，提供当前发言、同群上下文及最多各 100 条的人员／标签目录，不提供外群原文。准备／规划失败只重试该来源，后续准备完成的文字继续处理；规划错误回复固定暂不可用提示。每次异步交接复核当前群授权、来源状态和渠道设置，配置变化或撤销使旧计划失效；发送前同时检查请求来源和查询结果是否仍有效。
- 完成提取后才查询最新有效书库并发送自然回复。处理成功后重复事件及正常重启不重复回复；数据库完成标记与 QQ 发送之间为尽力交付，崩溃或出站被拦截可能漏发，未实现跨崩溃的精确一次交付。失败重试可能再次发送暂不可用提示。
- 成功处理且没有小说条目的普通聊天，原文、媒体引用和识别缓存默认保留 7 天后清空。为避免重复入队，消息 ID、身份、时间和处理状态仍保留；小说讨论来源原文、媒体引用、识别文本和结构化条目长期保留，撤销时清除对应本地内容。积压待处理原文不会被保留期限删掉，DSH 长期不可用时应注意磁盘空间。MVP 没有群内清库或自动清理全部历史的功能。
- 只记录机器人在线收到的消息，不拉取上线前历史，不展开合并转发，不确认平台或链接中的书籍信息。作者仅来自明确原文、识别文本或清楚的同群上下文；同名不同作者分开存，未知作者与已知作者暂不自动合并，别名也不自动合并。
- 模型可能漏掉或误解推荐、观点和指代。来源验证可以阻止伪造消息 ID、身份和引用原文，无法保证所有语义判断正确；发现误记录请引用撤销后重新明确描述。原文、识别文本和实际图片字节会发送到既有 DSH 模型服务，启用前应告知群成员。桥接 SQLite 保存媒体引用与识别文本；DSH 可能将图片保留为自己的提示附件。会话归档或本地撤销不保证删除 DSH 历史提示／附件，远端数据保留遵循已有 DSH／模型服务配置。

## 离线检查与演示

```bash
npm run test:bookbot
npm run demo:bookbot
node --check src/bridge.js
```

测试和演示使用临时目录与固定提取／自然规划夹具和模拟 DSH，不读取真实凭据，不连接 QQ，不发送消息。演示包含文字推荐、评价、截图分享不计推荐人、QQ 语音推荐及自然提问、自然复合查询、无关内容固定回复、查书与撤销后的结果，并删除临时库。本 MVP 尚未进行真实 QQ/DSH 往返验证。
